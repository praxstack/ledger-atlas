Not a finished product

Count the full plan as about one fifth done. Count a shipped app as zero.

Ledger Atlas is a money app we build from zero. The goal is to keep your money records in our database — the canonical ledger — not in Money Manager.

You asked if the project is complete. An earlier answer mixed five different questions. That is why the percentages fought each other. This page answers only the question you asked.

Think of a house. The kitchen machines are in the garage and they run. There is no street address, no front door key, and no inspector sign-off. You cannot move in.

The engine works on fake test data. Tests pass. The Mac window can open a test ledger. That is real. It is not the same as: install this, import my backup, and trust every amount.

What already works

We can look at a Money Manager file without changing it. We can name the source profile (the exact backup type). We can keep unknown pieces in a sidecar (the original bytes, stored as-is). A LossReport must list every source item as mapped, kept, excluded with a reason, or blocking.

On fake test data we can create an Entry, an Account, and a Transfer. We can split a purchase, run an installment plan, search, report, export, and restore. The Mac journey can review a test source and open the imported ledger.

We do not have a lossless import certificate for a real Android v19 backup. Certified cells: 0. Universal compatibility: false. Product source exists in local Git, but it is still an implementation candidate, not a shipped app.

Two facts that still block delivery

1. The supplied real backup has not completed a verified import. Candidate importer code and synthetic tests exist. There is no private reconciliation result proving that every supplied source item populated Ledger Atlas without silent loss.
2. A real Money Manager backup cannot get a lossless import certificate yet. Some vendor codes are still unknown. If I guess, I can invert a sign or drop a photo. You must either give a proven meaning, or accept a Ledger Atlas rule that we write down. Until then, the LossReport must stop rather than hide a gap.

I can keep building the Mac app on the canonical ledger we already have. I cannot pretend your real backup is imported. I cannot put this on the App Store.
